# Presentation order pack

In the live app, sign in as administrator, open New order / Excel and choose Load demo orders. The authenticated admin-only POST /api/demo-orders endpoint adds eight fictional orders for each of yesterday, today and tomorrow using Kuwait local dates. The pack is persistent in the configured database, unlike /demo's isolated browser samples. It requires no schema migration.

References begin MAWADA-DEMO-YYYY-MM-DD-. Demo metadata and order-card notices identify simulated records, milestones, proof contacts and coordinates. Data must not be represented as genuine operational evidence. Includes pending pickup, picked up, warehouse consolidation, out for delivery and delivered states; some slots/pickup deadlines are missed deliberately for charts. Historical/scheduled timestamps are fictional scenario times, including future-dated examples for tomorrow. No customer notifications are sent and all phone numbers are dummy +96500000000. Vendors have fictional pickup descriptions, not navigable real addresses. No invented live GPS trail or live device location is provided.

Three marked DEMO driver users are created with random unshared password hashes and example.invalid emails. They support dashboard workload comparisons, not demonstration driver logins. Create a normal driver account separately for interactive authenticated phone workflows. Existing real orders, vendors and user accounts are preserved. Stable demo reference numbers avoid duplicate examples on same-day retries. Order insertion is an atomic batch; vendor/user fixtures are created first and can remain if order insertion fails. A retry reuses these marked fixtures. Existing conflicting fixture IDs are rejected. Concurrent submissions may return a conflict; retry after the first finishes.

Loading again on another day adds only the missing dates. These fictional records count in operational reports once loaded; use a dedicated demonstration database if real-business reporting must remain separate. No automatic cleanup or delete-all behaviour is introduced. Restore/switch the chosen demo database through the normal backup/deployment process rather than deleting real orders indiscriminately.

Local tests cover authenticated admin loading, rejection for drivers, 24-order creation, multi-vendor examples, simulated proofs and idempotent repeat loading. Live Hostinger/database access was unavailable to the coding environment; the signed-in administrator must click the load button after deployment. Do not claim the live database has been populated until this action succeeds.
