# CMS delivery export template and supplied export review

New order / Excel includes Download CMS Excel template. Live GET /api/import/template requires admin/operations role plus create/import permission. It generates an ExcelJS workbook with first-sheet Orders, two fictional item rows for the same order, field guide and integration notes. The example date is the current Kuwait day. A static fictional template is supplied for the isolated demo; its example date must be changed when used later. Remove example rows, and use actual registered vendor codes/names. Phones/references/date columns are text; amounts have three decimal places.

Required columns: Order Number, Recipient Delivery Date, Recipient Name, Recipient Phone, Recipient Address, Vendor Name, Item Details, Quantity. Optional columns: Delivery Time Slot, Order Amount, Ring the bell, Extra direction, Card available, Occasion, Card message. One item per row, consistent repeated order fields, KWD order total rather than line-total summation, ISO dates and 24-hour slots are documented. Today-only filtering uses Recipient Delivery Date in Kuwait time. Unknown bell/card values stay blank; card price is not a proxy for physical presence. Occasion inference remains reviewable rules, not a connected AI model.

The supplied workbook has 34 columns, a worksheet extent of 39,729 rows, but 13,417 populated data rows plus header; blank gaps account for the difference. It is private reference data, not committed or imported. Core mappings are ORDER_NO → Order Number (PROVISIONAL), RECIPIENT_DELIVERY_DATE → Recipient Delivery Date, RECEIVER_NAME/PHONE → recipient, RECIPIENT_TIME_SLOT → slot, VENDOR_NAME → vendor, QTY_SOLD → quantity (must confirm item-level meaning), ORDER_AMOUNT → total (must confirm order-level meaning). Source dates use month-name text; CMS should emit ISO YYYY-MM-DD.

Missing fields: full recipient address, item description, bell preference, extra directions, card availability, explicit occasion/card message. DELIVERY_AREA is retained in the private cleaned review as reference, not presented as a full address. PARENT_ORDER_NO is also retained: CMS must confirm whether parent or child identity defines the consolidated delivery. Do not guess or import an incomplete grouping. SECRET_GIFT is preserved as a CMS privacy reference, but current importer does not enforce anonymous/surprise masking. Do not assume sender/item/message privacy controls exist simply because a source flag exists.

Sender contact details, payment method, encashed/refunded amounts, COD/delivery/tax/discount/loyalty/wallet/card/media charge breakdowns, gift-resolution workflow and internal source metadata are unnecessary in the minimal delivery template; retain them in CMS. Source status and cancellation rules must be applied by CMS before export: the importer currently filters delivery date, not source payment/cancellation eligibility. Do not interpret a day match as approval to fulfil a cancelled order.

A private cleaned REVIEW workbook retains all 13,417 populated rows, with missing required address/item fields blank so it cannot be imported accidentally. It includes source parent reference, source area and source secret-gift flag plus explicit review instructions. No real data is served by the application, committed to GitHub or added to sample orders. File outputs are in the task's shared export-review folder for authorised user download only.

Template tests round-trip Excel through the actual Mawada parser, checking multi-item grouping, money and bell values. API tests cover download authorization. Live download/deployment remains subject to Hostinger deployment verification.
